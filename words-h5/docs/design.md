## 1. 文档概述

本文档基于 `proposal.md` 给出**前后端技术实现方案**，包括：数据库设计（复用已有 `books` / `words` 表）、数据访问层、认证与中间件改造、路由与页面设计、核心组件、Server Actions、数据导入方案与边界处理。

实现遵循两条原则：

1. **最小侵入**：登录 / 注册（`auth.ts`、`db.ts` 的 `getUser` / `createUser`）、通用表单（`form.tsx`、`submit-button.tsx`）直接复用，不重写。
2. **零迁移工具**：新表沿用项目现有的「DDL 手动建表 + Drizzle schema 定义」模式，不引入 migration 框架。

### 3.2 必须改造：`auth.config.ts` 的 `authorized` 回调

**现状问题**：当前逻辑会把**已登录**用户访问 `/` 等非 `/protected` 页面强制重定向到 `/protected`，H5 主流程（已登录用户访问首页）会被打断。

**改造方案**：中间件只对「必须登录」的路由设卡（`/study/*`），其余页面全部放行，登录门槛由页面 / 交互层控制（详见 6.2）。

```ts
// app/auth.config.ts（改造后）
authorized({ auth, request: { nextUrl } }) {
  const isLoggedIn = !!auth?.user;
  const { pathname, search } = nextUrl;

  // 学习页需要登录：未登录 → 跳【我的】并自动弹登录 popup，携带回跳地址
  if (pathname.startsWith('/study')) {
    if (isLoggedIn) return true;
    const loginUrl = new URL('/mine', nextUrl);
    loginUrl.searchParams.set('auth', '1');
    loginUrl.searchParams.set('back', pathname + search);
    return Response.redirect(loginUrl);
  }

  return true; // 其余页面全部放行（首页未登录也要能浏览单词书）
},
```

`middleware.ts` 的 matcher 保持不变（仍覆盖页面路由）。

## 4. 数据库设计

### 4.1 已有表（不改动）

**books（单词书）**

```sql
create table public.books (
  id bigint generated by default as identity not null,
  title character varying(255) not null,
  word_count integer not null default 0,
  cover_url text null,
  book_id character varying(100) not null,
  tags text null,
  created_at timestamp with time zone not null default now(),
  updated_at timestamp with time zone not null default now(),
  constraint books_pkey primary key (id),
  constraint books_book_id_unique unique (book_id)
);
```

**words（单词）**

```sql
create table public.words (
  id bigint generated by default as identity not null,
  "wordRank" integer null,
  "headWord" text null,
  content json null,
  "bookId" text null,
  constraint words_pkey primary key (id)
);
```

**User（用户，`app/db.ts` 运行时自动建表）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | SERIAL PK | 用户 ID |
| email | VARCHAR(64) | 邮箱 |
| password | VARCHAR(64) | bcrypt 哈希 |

> **注意**：PG 中 `"wordRank"` / `"bookId"` 是**大小写敏感的带引号标识符**，SQL 与 Drizzle 中必须始终带双引号书写，否则会被折叠成小写导致 `column does not exist` 错误。

**字段映射约定（words.content）**：导入时存储源 JSON 的 `content.word.content` 子对象，即包含 `sentence / usphone / ukphone / trans / phrase / syno / relWord / remMethod` 的那一层；`wordRank / headWord / bookId` 冗余成列便于排序与过滤。

**与 proposal 的路由差异说明**：`words` 表没有 `wordId` 列，单词详情页路由参数改用 `words.id`（自增主键）：`/word/[id]`。学习顺序仍以 `wordRank` 为准。

### 4.2 新增表：study_progress（学习进度）

```sql
create table public.study_progress (
  id bigint generated by default as identity not null,
  user_id bigint not null,
  book_id character varying(100) not null,
  last_word_rank integer not null default 0,
  created_at timestamp with time zone not null default now(),
  updated_at timestamp with time zone not null default now(),
  constraint study_progress_pkey primary key (id),
  constraint study_progress_user_book_unique unique (user_id, book_id)
);

-- 「最近学习」与「进度列表」查询
create index idx_study_progress_user_updated
  on public.study_progress (user_id, updated_at desc);
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint identity PK | |
| user_id | bigint | 关联 `User.id` |
| book_id | varchar(100) | 关联 `books.book_id` |
| last_word_rank | integer | 最近一次学习的单词 `wordRank`；`0` 表示刚开始（下一个从 1 开始） |
| updated_at | timestamptz | 每次学习刷新，「最近学习」按此倒序 |

`unique (user_id, book_id)` 保证一人一书一条进度，更新走 upsert。

## 5. 数据访问层（`app/db.ts` 扩展）

### 5.1 Drizzle 表定义

```ts
// app/db.ts 追加
import {
  bigserial, bigint, integer, json, pgTable, text,
  timestamp, varchar,
} from 'drizzle-orm/pg-core';

export const books = pgTable('books', {
  id: bigserial('id', { mode: 'number' }).primaryKey(),
  title: varchar('title', { length: 255 }).notNull(),
  wordCount: integer('word_count').notNull().default(0),
  coverUrl: text('cover_url'),
  bookId: varchar('book_id', { length: 100 }).notNull(),
  tags: text('tags'),
  createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
  updatedAt: timestamp('updated_at', { withTimezone: true }).notNull().defaultNow(),
});

// 已有表列名为带引号的驼峰，Drizzle 列名参数必须写成 '"xxx"'
export const words = pgTable('words', {
  id: bigserial('id', { mode: 'number' }).primaryKey(),
  wordRank: integer('"wordRank"'),
  headWord: text('"headWord"'),
  content: json('content'),
  bookId: text('"bookId"'),
});

export const studyProgress = pgTable('study_progress', {
  id: bigserial('id', { mode: 'number' }).primaryKey(),
  userId: bigint('user_id', { mode: 'number' }).notNull(),
  bookId: varchar('book_id', { length: 100 }).notNull(),
  lastWordRank: integer('last_word_rank').notNull().default(0),
  createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
  updatedAt: timestamp('updated_at', { withTimezone: true }).notNull().defaultNow(),
}, (t) => ({
  userBook: unique('study_progress_user_book_unique').on(t.userId, t.bookId),
}));
```

### 5.2 查询函数清单

| 函数 | 签名 | 说明 |
| --- | --- | --- |
| `getBooks` | `(): Promise<Book[]>` | 首页单词书列表，按 `id` 排序 |
| `getBookByBookId` | `(bookId): Promise<Book \| undefined>` | 书详情页头部 |
| `getWordsByBookId` | `(bookId): Promise<Word[]>` | `where "bookId" = ? order by "wordRank" asc nulls last, id asc` |
| `getWordById` | `(id): Promise<Word \| undefined>` | 详情页，返回含 `content` 完整字段 |
| `getLatestProgress` | `(userId): Promise<ProgressItem \| undefined>` | 最近学习：按 `updated_at desc` 取 1 条，join `books` |
| `getProgressList` | `(userId): Promise<ProgressItem[]>` | 【我的】进度列表，按 `updated_at desc`，join `books` |
| `getProgress` | `(userId, bookId)` | 学习页定位起点 |
| `upsertProgress` | `(userId, bookId, wordRank)` | `on conflict (user_id, book_id) do update set last_word_rank, updated_at = now()` |

**学习序列约定**：`getWordsByBookId` 返回即学习顺序（`wordRank` 升序、null 排最后、`id` 兜底）。「下一个」按**数组下标 +1** 推进，不依赖 `wordRank` 连续性；`last_word_rank` 记录当前卡片对应单词的 `wordRank`。

### 5.3 建表兜底

沿用 `ensureTableExists` 模式：`upsertProgress` / 查询前检查 `study_progress` 是否存在，不存在则执行 4.2 的 DDL（与现有 `User` 表处理一致）。

## 6. 认证与会话设计

### 6.1 登录 / 注册（popup 内）

复用现有能力，popup 表单提交到 Server Action：

- **登录**：`signIn('credentials', { email, password, redirectTo })`（同 `app/login/page.tsx` 写法）。
- **注册**：`getUser(email)` 判重 → `createUser(email, password)` → `signIn(...)` 自动登录（同 `app/register/page.tsx` 逻辑合并为一个 action）。
- 失败处理：捕获 `CredentialsSignin` 等 NextAuth 错误码，`redirect()` 回 `/mine?auth=1&back=...&error=1`，popup 读取 `error` 展示提示（URL 驱动，避免引入额外状态管理）。

### 6.2 登录门槛分层

| 场景 | 拦截层 | 行为 |
| --- | --- | --- |
| 首页点击单词书（未登录） | 页面层 | 服务端 `auth()` 判断，渲染为 `/mine?auth=1&back=/book/{bookId}` 跳转链接 |
| 首页点击【最近学习】（未登录理论上不可见，不处理） | — | 模块仅登录后渲染 |
| 直接访问 `/study/*`（未登录） | 中间件 | 见 3.2，重定向 `/mine?auth=1&back=...` |
| 保存进度（未登录） | Action 层 | `saveProgress` 内 `auth()` 无 session 则静默忽略（兜底防御） |

### 6.3 退出登录

【我的】页退出按钮 → Server Action 调用 `signOut({ redirectTo: '/mine' })`，session 清除后页面自然回到未登录态。

### 7.2 页面规格

| --- | --- | --- | --- |

## 8. 核心组件设计

### 8.1 BottomNav（底部 Tab）

- `'use client'`，`usePathname()` 判断高亮；两个入口：`/`（首页）、`/mine`（我的）。
- 固定底部（`fixed bottom-0`），内容区预留 `pb-16` 防遮挡；仅出现在 `(tabs)` 组页面。

### 8.2 AuthPopup（登录 / 注册弹窗）

```
props: { initialOpen: boolean; back?: string; error?: string }
状态: open / mode('login' | 'register')
```

- 服务端把 `/mine` 的 `searchParams`（`auth`、`back`、`error`）转为 props，`auth=1` 时初始打开。
- 关闭时 `router.replace('/mine')` 清理 URL 参数（刷新后不再弹）。
- 内容为两个 `<Form>`（复用 `form.tsx`），分别 action 到 `actions.ts` 的 `loginAction` / `registerAction`，提交按钮复用 `SubmitButton`（自带 pending 态）。
- `back` 作为隐藏字段随表单提交，登录成功后 `redirect(back ?? '/')`。

### 8.3 WordCard（学习卡片）

- `'use client'`，props：`StudyCard`、`onNext()`、`index`、`total`。
- 渲染：`headWord`（大字）→ 音标（英 / 美）→ `tranCn` → 示例（`sContent/sCn`，为空降级 `pContent/pCn`，再空隐藏）→「点击查看详情」提示；整体可点击 `router.push(/word/${id})`。
- 【下一个】按钮：调用 `onNext`（内部触发 Server Action + 切换下标），最后一个词时按钮置灰并显示「已完成」。

### 8.4 WordDetail（单词详情各 section）

纯 Server 渲染，按模块拆子组件：`TransSection` / `SentenceSection` / `PhraseSection` / `SynoSection`（按 `pos` 分组）/ `RelWordSection`（按 `pos` 分组）/ `RemMethodSection`。约定：**模块数据缺失（null / 空数组）时返回 null 不渲染**。

## 9. Server Actions 设计（`app/actions.ts`）

```ts
'use server';

// 1) popup 登录
export async function loginAction(formData: FormData) {
  // formData: email / password / back
  try {
    await signIn('credentials', { redirectTo: back || '/' });
  } catch (e) {
    if (e instanceof AuthError) {
      redirect(`/mine?auth=1&back=${back}&error=1`); // popup 内展示错误
    }
    throw e; // redirect() 抛出的 NEXT_REDIRECT 必须继续抛出
  }
}

// 2) popup 注册（判重 → 建号 → 自动登录）
export async function registerAction(formData: FormData) {
  // getUser 判重：已存在 → redirect(...&error=exists)
  // createUser(email, password)
  // signIn('credentials', { redirectTo: back || '/' })
}

// 3) 学习进度保存（学习页【下一个】触发）
export async function saveProgress(bookId: string, wordRank: number) {
  const session = await auth();
  if (!session?.user) return { ok: false };            // 未登录静默忽略
  await upsertProgress(session.userId, bookId, wordRank);
  return { ok: true };
}

// 4) 退出登录
export async function signOutAction() {
  await signOut({ redirectTo: '/mine' });
}
```

注意事项：

- Server Action 中调用 `signIn` / `redirect` 会抛出 `NEXT_REDIRECT` 控制流异常，`try/catch` 里必须重新 throw 非业务错误。
- `session.userId` 来自 NextAuth JWT：`authorize` 返回的 `user[0]` 含 `id` 字段，session 回调透传（若默认策略取不到，在 `authConfig.callbacks.jwt / session` 中补充 `token.id = user.id`）。

## 10. 关键流程时序

### 10.1 未登录点击单词书 → popup 登录 → 回跳

```
  │ 点击书A                   │                        │                   │
  ├──────────────────────────►│                        │                   │
  │                           │ auth()=null            │                   │
  │◄──链接 /mine?auth=1───────┤                        │                   │
  │      &back=/book/A        │                        │                   │
  │ 跳转───────────────────────────────────────────────►│                   │
  │                           │                        │ auth=1 → 初始打开  │
  │◄──────popup HTML───────────────────────────────────┤                   │
  │ 输入邮箱密码，提交 loginAction                       │                   │
  ├───────────────────────────────────────────────────►│ signIn('credentials')
  │                           │                        ├──────────────────►│
  │                           │                        │◄── session cookie─┤
  │◄── redirect(back) → /book/A ───────────────────────┤                   │
```

### 10.2 学习进度推进

```
/study/[bookId] (Server)
  │ progress = getProgress(uid, bookId)      // { lastWordRank } | undefined
  │ cards    = getWordsByBookId → toStudyCard // 精简投影数组
  │ startIdx = progress ? (lastWordRank 所在下标 + 1) : 0
  │           // 若 lastWordRank 是最后一词 → startIdx = 0（学完从头）
  ▼
<WordCard cards[startIdx]> (Client)
  │ 点击【下一个】
  ├─► saveProgress(bookId, cards[idx+1].wordRank)   // Server Action, upsert
  └─► setIdx(idx + 1)                               // 本地切卡，无整页刷新
  │ 点击卡片本体 → 跳 /word/{id} → 返回后进度状态保留在浏览器历史中
```

定位说明：`startIdx` 通过 `wordRank → 下标` 映射计算（`cards.findIndex(c => c.wordRank === lastWordRank)`），不假设 `wordRank` 连续。

## 11. 数据导入方案（`scripts/import-words.ts`）

**输入**：`words-admin/temp/*.json`，每行一个单词对象（NDJSON，末行可能无换行）。
**运行**：`npx tsx scripts/import-words.ts`（幂等，可重复执行）。

```
处理流程（每本书）:
1. bookId = 文件名去 .json 扩展名（如 PEPXiaoXue3_1）
2. 逐行 JSON.parse；容错：跳过空行，解析失败打印行号并继续
3. upsert books：book_id 冲突则更新 title / word_count
   - title 从 TITLE_MAP[bookId] 取，缺省用 bookId（人工维护映射表）
   - word_count = 本文件成功解析的行数
4. 批量插入 words：
   - "bookId" = bookId，"wordRank" = wordRank，"headWord" = headWord
   - content = 源 JSON 的 content.word.content（见 4.1 约定）
   - 先 delete from words where "bookId" = bookId 再插入（保证重跑幂等）
5. 打印统计：每本书插入条数 / 失败条数
```

## 12. 边界与异常处理

| 场景 | 处理 |
| --- | --- |
| `words.content` 为 null | 卡片只显示 `headWord`；详情页各模块全部隐藏 |
| `wordRank` 为 null | 排序时 `nulls last`，学习序列仍可推进，进度记录其 `wordRank`（null 不写入，记 0 前后语义由下标兜底） |
| `trans` 为空但卡片需释义 | 卡片释义区隐藏；例句、短语同理逐级降级（proposal FR-7） |
| 已学完整本书 | 学习页 `startIdx` 回绕到 0（从头复习），顶部显示「已完成一轮」 |
| 书无单词 / bookId 不存在 | 详情 / 学习 / 单词页 `notFound()`（404） |
| popup 登录失败 | `error=1` 回显「邮箱或密码错误」；注册判重 `error=exists` 回显「用户已存在」 |
| `lastWordRank` 对应词被重新导入删除 | `findIndex` 返回 -1 → 回退到 `startIdx = 0` |
| 弱网下【下一个】重复点击 | `SubmitButton` pending 态禁用 + 卡片切换按钮本地防抖 |

## 13. 安全设计

| 项 | 措施 |
| --- | --- |
| 会话 | NextAuth JWT httpOnly cookie，`/study/*` 由中间件设卡 |
| 越权 | `saveProgress` 不接受客户端传 `userId`，一律取 `auth()` session；bookId 校验存在于 `books` |
| 注入 | 全部查询经 Drizzle 参数化，无字符串拼接 SQL |
| 密码 | `bcrypt-ts` 哈希（沿用 `createUser`），不存明文、不回传 |
| 输入 | 邮箱格式 / 密码非空在表单 `required` + Action 内二次校验 |
